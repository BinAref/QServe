v1.0.19

Writing a version here and pushing it is how a release is cut: the workflow in
.github/workflows/release.yml builds the Windows bundle and the Android
terminal, tags this commit, and publishes both. Only the first line is read;
everything after it is for whoever opens this file next.

Pushing this file again re-runs the build and updates the release in place, so
a fix to the packaging does not need a new version number.

Before cutting a release anyone is meant to pay for, three repository secrets
have to exist or the workflow refuses to publish:

  QSERVE_TRUSTED_KEYS  the public half of `npm run keygen`, so an activation
                       certificate can be verified with the internet unplugged
  QSERVE_VENDOR_URL    where a build asks for a licence
  QSERVE_VENDOR_INFO   who a restaurant contacts to buy one, with at least one
                       contact in it

The third was a warning until 1.0.18 and was never set, so five releases went
out telling restaurants to "ask us" above an empty space. Nothing in the test
suite could see it; starting the published exe did.
