v1.0.6

Writing a version here and pushing it is how a release is cut: the workflow in
.github/workflows/release.yml builds the Windows bundle and the Android
terminal, tags this commit, and publishes both. Only the first line is read;
everything after it is for whoever opens this file next.

Pushing this file again re-runs the build and updates the release in place, so
a fix to the packaging does not need a new version number.

Before cutting a release anyone is meant to pay for: run `npm run keygen` and
put the public half in the QSERVE_TRUSTED_KEYS repository secret, and prepare
the vendor details in the console's Developer section (or QSERVE_VENDOR_INFO),
or the build ships unable to activate anything and with nobody to ask.
